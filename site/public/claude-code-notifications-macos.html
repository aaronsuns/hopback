Claude Code notifications on macOS

A Claude Code session that stops to ask permission just sits there until you notice. This page covers how to get notified on a Mac, from a do-it-yourself hook to a menu bar app that tracks every session.

macOS 13 or newer, Visual Studio Code with the Claude Code extension. Source on GitHub.

Why you miss "Claude is waiting"

Claude Code runs long tasks, but it pauses when it needs you: to approve a tool call, to answer a question, or to review a plan. If you are in another window or another app, nothing tells you. With several sessions, the one that has been waiting for twenty minutes is usually the one you forgot about.

Option 1: write your own hook

Claude Code has hooks, commands it runs on events. One of those events is Notification, which fires when Claude Code sends a notification, for example when it needs permission. You can point it at a shell command that shows a macOS notification. A minimal example in your Claude Code settings:

"hooks": { "Notification": [ { "hooks": [ { "type": "command",
  "command": "osascript -e 'display notification \"Claude Code needs you\" with title \"Claude Code\"'" } ] } ] }

This is the lightest option and needs no extra software. Check the Claude Code documentation for the exact settings format, since it can change. What a DIY banner does not give you is a running overview: you do not know which session called, or how many are waiting now.

Option 2: Hopback, a menu bar view of every session

Hopback installs a small Claude Code plugin that listens to Claude Code's hook events (including Notification, PermissionRequest and Stop) and records one status file per session. The Hopback app reads those files and gives you:

  • A banner when a session starts waiting for you. Click it to go straight to that session.
  • A menu bar summary such as ⚠1 ⚙2 · ▢8: one needs you, two are working, eight VS Code windows show a session.
  • A Needs you list with every waiting session, whether or not a window shows it. ⌃⌥0 jumps to the next one, and again to the one after.
  • Glyphs per session: ⚠️ approve a tool call, ❓ answer a question or review a plan, ⚙️ working, 💤 finished.

The plugin writes only a small status file per session to ~/.claude/hopback/. If Hopback is not installed, the plugin does nothing.

Set it up

  1. Download Hopback from the latest release, drag it to Applications and clear the quarantine flag once: xattr -dr com.apple.quarantine /Applications/Hopback.app
  2. Open it and follow the welcome window: Accessibility, the plugin, notifications and start at login.
  3. Or install the plugin by hand: claude plugin marketplace add aaronsuns/hopback then claude plugin install hopback@hopback.
  4. Open a new Claude Code session; sessions that were already open do not load new plugins.

If no banner appears, use Send test banner in the welcome window, then check System Settings, then Notifications, then Hopback. The menu's Diagnostics shows whether the plugin is installed and has run. More on the mechanism in Claude Code hooks for session status.

Frequently asked questions

Does Claude Code have built-in notifications?

Claude Code has a Notification hook that you can wire to a command of your own. Check the Claude Code documentation for what it offers on your version. Hopback builds on the hook events to add a menu bar overview.

Do I need the plugin for banners?

Yes. The plugin is what tells Hopback a session is working or waiting. Without it, Hopback still lists windows and searches history, but cannot tell when a session needs you.

What does the plugin write to disk?

One small status file per session in ~/.claude/hopback/, and nothing else.

Does it work with the VS Code extension and the terminal?

Banners and the Needs you list cover both, but only VS Code windows are listed and raised.
