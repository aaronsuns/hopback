Hopback / Claude Code in multiple VS Code windows

Running Claude Code in multiple VS Code windows

One window per project is the natural way to run several Claude Code sessions at once. It also makes it easy to lose the thread. Here is a workflow that keeps it manageable.

One folder, one window, one session

The simplest rule is to keep each project in its own VS Code window with its own Claude Code conversation. It keeps context clean, and it lets you reason about state: this window is the API, that one is the docs. The trouble starts around the fourth window, when the Dock shows identical icons and you cannot tell which one is blocked.

Give every window a stable number

Hopback numbers your VS Code windows from A to Z by folder name and keeps that order, so the number of a project does not change when you reorder windows with the mouse. The menu lists them as 1, 2, 3 and so on, each with the session it shows. Press ⌃⌥1 to ⌃⌥9 to go to that window, from any app and any Space. ⌃⌥⇥ and ⌃⌥⇧⇥ step to the next and previous VS Code window.

Always know which session needs you

The menu bar summary, for example ⚠1 ⚙2 · ▢8, counts sessions waiting for approval (⚠), working (⚙) and the VS Code windows showing a Claude Code session (▢). Press ⌃⌥0 to go to the next session that needs you, and press it again for the one after. The Needs you section lists those sessions even when no window currently shows them. A banner tells you at the moment a session starts waiting. See Claude Code notifications on macOS.

Sessions with no window

Some sessions are busy but not shown in any window, for instance a session started in a terminal. Hopback lists them under Working in background, so you can see them and jump to them. Clicking one opens its folder in VS Code and then the conversation.

Get back to an old session

Closed a window and now need that conversation? Press ⌃⇧⌘C and type part of the title or the folder. With three or more characters Hopback also searches the conversation text and shows a snippet around the hit. Details in searching Claude Code history.

A practical routine

  1. Start each task in a window named for its folder, and let Claude Code run.
  2. Work in the foreground window; glance at the menu bar count.
  3. When the count shows a warning, press ⌃⌥0, approve or answer, and go back.
  4. When a task is done, close the window; the conversation stays searchable in history.

Frequently asked questions

How are the window numbers chosen?

Hopback numbers VS Code windows from A to Z by folder name, as shown in the menu, and ⌃⌥1 to ⌃⌥9 go to windows 1 to 9. You can change the shortcuts in Settings.

Can Hopback raise a window on another Space?

Yes. If a window shows the session, Hopback brings it to the front even from another Space. Otherwise it opens the folder in VS Code and then the conversation.

Why is the session shown for a window sometimes wrong?

VS Code saves which conversation a window shows every so often, not instantly, so Hopback can lag a few seconds. Until then it guesses the most recently active session in that folder.

Does it need special permissions?

Accessibility, so Hopback can list VS Code's windows and raise one, and notification permission for banners.
