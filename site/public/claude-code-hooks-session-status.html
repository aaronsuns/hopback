Hopback / Claude Code hooks for session status

Using Claude Code hooks to track session status

Claude Code runs commands for you at defined moments in a session. Hopback uses those hooks to learn whether each session is working or waiting. This is how it works, in enough detail to trust it.

What Claude Code hooks are

Hooks are commands that Claude Code runs on events in a session, for example when a session starts, before a tool runs, when it needs permission or when a turn ends. They are configured in settings or shipped in a plugin. They are the supported way to react to what a session is doing from outside Claude Code.

The events Hopback listens to

The Hopback plugin registers a hook for these events: SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure, Notification, Stop and SessionEnd. From that sequence Hopback can tell the four states it shows:

StateGlyph
waiting to approve a tool call⚠️
waiting for an answer or a plan review❓
working⚙️
finished its turn, nothing pending💤

What the plugin does with each event

Each hook runs a tiny program that lives inside Hopback.app, hopback-hook. It writes one small status file per session to ~/.claude/hopback/ and nothing else. If Hopback is not installed the hook command checks that the program exists and otherwise just discards its input, so the plugin does nothing and does not slow Claude Code down.

Install the plugin

The welcome window's Install plugin button does it for you. By hand, run these in a terminal (the Claude Code panel in VS Code has no /plugin command):

claude plugin marketplace add aaronsuns/hopback
claude plugin install hopback@hopback

Then open a new Claude Code session or reload the VS Code window, because sessions that were already open do not load new plugins.

Check that it works

Open Diagnostics from the Hopback menu. It shows whether the plugin is installed and has run, and Copy report gives you text for a bug report that contains no conversation text. If sessions never show ⚠️ or ❓, the usual cause is that the plugin is missing or that the session started before it was installed.

Remove it

Uninstall with claude plugin uninstall hopback@hopback and remove the marketplace, then delete ~/.claude/hopback if you want the status files gone. The README has the full list of what to remove.

What this enables: notifications when Claude Code is waiting and the session switcher for VS Code. Get Hopback from the latest release.

Frequently asked questions

Is the Hopback plugin safe to install?

It runs one small program from Hopback.app on Claude Code hook events and writes a status file per session to ~/.claude/hopback/. The source is on GitHub under the MIT licence so you can read it.

Does the plugin slow Claude Code down?

Each hook has a 5 second timeout, and the command only runs the Hopback program if it is installed. Otherwise it discards its input and exits.

Why do sessions not show warnings?

Install the plugin and then start a new session. Sessions that were already open do not load new plugins. Diagnostics in the Hopback menu shows whether the plugin has run.

Does the plugin read my conversation?

The plugin writes status files only. Conversation text is read separately by Hopback's history index on your Mac, for search, and is never written to its log.
